# Dedicated CRM source credential handoff v1

This operator-only path prepares the already approved 66-task/11-project run without exposing a source credential to the native AI or browser. It creates no authority by itself. Existing CRM connections must not be rotated. The one-hour clock starts at Roles activation; setup consumes that same hour and cannot extend it.

CRM must verify the original Roles activation receipt with the pinned Roles decision key using `Bittrees MCP lease activation receipt v1\n` plus sorted-key canonical JSON. Use the strict receipt schema in Roles `shared/mcp-lease.mjs`; check owner profile from tenant, current workspace authority, sourceWorkspace, exact approved mappings, principal/key/runtime binding, audience, nonrenewable status, and actual unexpired one-hour interval before consent creates anything. A receipt alone does not prove current authorization. Recheck revocation/current authority where required; the MCP gateway always performs a fresh Roles decision before any effect.

`src/service/source-handoff.mjs` exports `sealSourceHandoff`, `openSourceHandoff`, `recipientKeyId`. Node built-in crypto only; `roles-proof.mjs` provides sorted-key canonical JSON. CRM may vendor these two exact helper files with provenance and interop tests. Do not accept encryption recipient or signing keys from browser input.

Metadata exact fields: `version:1`, `issuer:https://crm.bittrees.org`, `audience:https://mcp.bittrees.org`, `handoffId` UUID, `connectionId` UUID, `leaseId` UUID, `policyDigest` 64 lowercase hex, `tenant:roles:<owner-profile-UUID>`, `workspace:crm:<sourceWorkspace>`, `principal:agent:<UUID>`, `credentialId` 64 lowercase hex, `runtimeBindingDigest` 64 lowercase hex, `sourceWorkspace` UUID, `mappingDigest` 64 lowercase hex, `activatedAt`, `expiresAt`, `recipientKeyId` 64 lowercase hex. Normalize verified receipt timestamps with `new Date(value).toISOString()` only after verifying the original signature. Metadata has canonical millisecond UTC timestamps; exact interval is 3,600,000 ms.

Mapping digest is SHA256(canonical(manifest)), manifest `{feedRevision,sourceWorkspace,mappings}`. Mapping entries are exactly `{sourceProjectId,crmProjectId,siteUrl}`, sorted by sourceProjectId using ASCII lexical comparison. The private local review is `operations/local-ai-task-sync-2026-10-17/source-handoff-mapping-review.json` in the shared project root. The approved digest is `ff21e4e9f641cc773107562741c20c85d33e300b87101a409f8b7a6e8e160beb`; do not reinterpret this approval as authorizing other mappings/revisions. CRM checks the pinned reviewed manifest, not a browser-provided digest alone.

Recipient key is a dedicated operator RSA key (minimum3072 bits). `recipientKeyId` is SHA256(SPKI DER public key). Private key stays in a mode0600 local operator file. CRM has only the configured public recipient key. CRM uses a separate dedicated Ed25519 private signing key; operator pins its public key through trusted deployment configuration. Neither key is a wallet or grant. Provision keys during authorized setup, never log them or put them in review artifacts.

Envelope exact fields: `{metadata,encryptedKey,iv,ciphertext,tag,signature}`, all byte fields canonical unpadded base64url. Encrypt token bytes using a fresh AES256GCM key and 12-byte IV with canonical(metadata) as AAD; encrypt AES key using RSA-OAEP-SHA256. Sign prefix `Bittrees CRM sealed source handoff v1\n` plus canonical(envelope without signature) using CRM Ed25519 signing key. Browser may receive only signed ciphertext and public metadata, never plaintext source token.

CRM atomically creates a dedicated fresh draft, connection token hash, exact approved grants and consent receipt only after fresh authenticated owner consent with CSRF protection. The dedicated source connection and grants expire at receipt.expiresAt. Persist the sealed envelope for recovery. Unique(owner,leaseId) plus exact immutable request digest enforces retry: replay original envelope for identical requests while consent/connection/membership remains valid; conflict on changed recipient/mapping/receipt rather than rotate. Expired or revoked connections cannot be renewed through retry. Owner approval must clearly show destination projects, local AI operator and remaining expiry.

Operator retrieves the envelope through the authenticated consent flow. Independently construct expectedMetadata from verified owner consent, pinned mapping review and signed Roles receipt; never copy expectedMetadata wholesale from an untrusted envelope. `scripts/open-source-handoff.mjs` takes five file paths: envelope, expected metadata, operator private key, pinned CRM public key, new output. It verifies signature and exact context, rejects stale or changed handoffs, and writes `{token,sourceWorkspace,expiresAt}` into a new mode0600 file without printing credentials. This is partial private source configuration: the operator still supplies the separately generated nativeToken and enrolled actor binding. Never reuse the CRM token as nativeToken. Existing output files are not overwritten. No public credential ingestion endpoint is added.

Release gate: CRM must test the actual helper roundtrip with the MCP opener and its consent persistence/authorization; key provisioning, owner consent and source configuration remain pending until that path and the real enrollment are ready. No live tokens or grants were created while developing this contract.
