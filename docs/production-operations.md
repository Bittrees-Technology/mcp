# Production operations

The independent repository is Bittrees-Technology/mcp; Vercel project is bittrees-mcp (`prj_dyKwSkVkZiafZMpxIkYsTDTmusb0`), linked to main. Node 22 is pinned. The only custom domain managed here is mcp.bittrees.org. Agent has its own task, repository, deployment and legacy contribution API.

Dedicated Neon resource: bittrees-mcp-production, Free plan, cle1. The integration's owner credentials were removed from the serving project after provisioning. Serving functions use `mcp_runtime`, with schema USAGE and SELECT/UPDATE on the single application-state table; no DDL or role creation. All connections use sslmode=verify-full. Migration credentials remain in the GitHub mcp-production environment, restricted to main. Runtime startup checks an existing migration; it cannot create tables.

Vercel production contains only dedicated MCP_DATABASE_URL, MCP_CREDENTIALS_JSON and MCP_WORKER_TOKEN secrets. GitHub environment secrets contain the migration/runtime connection, worker, backup key and scoped operator/validation tokens. No secret values belong in source, issues, artifacts or chat. A mode-0700 local recovery directory exists at ~/.codex/mcp-production-secrets with mode-0600 entries for the owner; keep it private. Service identities expire 30 days after initial provisioning. Rotate before expiry: generate a new random credential, update its hash/expiry and the recipient secret, redeploy and verify old-token denial. Worker and database passwords rotate independently. Existing Agent credentials are never forwarded.

Automations perform public-context reads only; private product actions are not implemented. Each new automation starts paused. The background worker processes only explicitly enabled definitions. Scheduled runs use a best-effort five-minute worker cadence. Public health verifies the durable store; it does not imply every listed product has a private API adapter.

Encrypted backups run every six hours and are retained as GitHub artifacts for 30 days. AES-256-GCM uses MCP_BACKUP_KEY stored separately in environment secrets and owner recovery storage. Initial decrypt/restore is tested against a local isolated temporary table. To verify a backup, set MCP_BACKUP_FILE, MCP_BACKUP_KEY and optionally a localhost-only MCP_RESTORE_TEST_DATABASE_URL, then run `node scripts/backup.mjs --verify`. Full production restoration requires a reviewed maintenance window and reconciliation of newer runs; the drill never overwrites production. Provider point-in-time recovery retention is not asserted without provider-console evidence.

CI tests PostgreSQL transactions, tenant/project isolation, rule denials, retry/pause/cancel and website routes. Production candidates should use `vercel deploy --prod --skip-domain` from a clean commit; scripts/release.mjs verifies the deployment's project, commit, state, durable health and scoped tools before assigning the MCP alias. Existing authenticated CLI access supports operator releases. Creation of a dedicated automated-release API token was refused by Vercel with 'Cannot create tokens for this app'; do not copy an unrelated account token or claim the GitHub release action is provisioned. The Git integration remains connected for source builds. Automated catalog publication must be verified against the deployed revision before being described as active.

Browser visual acceptance is currently unavailable because the administrator policy check fails. API and server-rendered route verification do not substitute for mobile/browser visual acceptance.
