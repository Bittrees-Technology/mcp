# Reusable project integration prompt

Integrate this product with the standalone Bittrees MCP service at
https://mcp.bittrees.org/mcp. Agent.bittrees.org is the onboarding funnel. Read docs/ecosystem-integration.md and the current
manifest and selection schemas first. Inspect the real repository and applicable
instructions. Reuse an existing product ID or component alias; do not create a
server for each contract, runtime or marketing repository.

Prepare bittrees.project.json with evidence-backed affiliation, accountable owner,
canonical repository/origins, lifecycle, source revision, public-resource adapter
and exact readiness. Keep unknown affiliation/endpoints pending. Do not claim
private API support from a landing page. Propose new private capabilities separately
with project/tenant/actor isolation, expiry/revocation, least scopes and negative
authorization tests. Never move secrets into manifests or selection URLs.

Register the source through the reviewed gateway policy. Demonstrate selected
pins, dynamic groups and exclusions, saved profile overrides,
new-project propagation, deprecation/reclassification, replay, failed-source
retention, and forbidden project calls. Configure authenticated repository events
and scheduled reconciliation through approved credentials. Record deployed revision,
observed propagation time, failure visibility, and rollback evidence before claiming
automatic updates are active. Report implementation, tests, deployment, and missing
owner/authority/configuration evidence separately. Node work is deferred; retain only its future ecosystem-default requirement in documentation. Use the standalone service’s versioned rules and durable automation contracts; catalog membership never grants execution authority.
