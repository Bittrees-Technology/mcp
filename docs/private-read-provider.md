# Disabled managed Mail and Insights reads

This implementation is preparation. The public function directory does not advertise these managed tools. Nothing creates a source connection, credential, enrolled actor, Roles grant, native consent or TLD approval.

Runtime defaults are `MCP_PRIVATE_READS_ENABLED` unset/false and `MCP_PRIVATE_READ_CONNECTIONS_JSON=[]`. Both the global flag and an individually enabled, finite-lived, exact actor/source connection are required even for authenticated tool discovery. No production configuration is changed by this release.

The typed tools are `private_insights_read_analytics`, `private_insights_export_analytics` and `private_mail_read_selected_message`. They require the selected project, current MCP actor credential and `sources:propose`, a matching existing Roles binding and approved connection. There are no write tools, user-supplied destination URLs, retries, background jobs or browser fallbacks.

This v1 family explicitly requires proofMode gateway-held-delegated-v1, an already approved gateway-held enrolled agent/service key and a current delegation. Device-held keys and native leases are denied before any source challenge/read. A future native flow needs a separately reviewed durable same-operation challenge/resume protocol; it must never upload the device private key or regenerate operation IDs as a fallback. No actual actor type has been verified.

An approved connection must bind tenant, subject, actorTokenHash, source, rolesAuthorityBinding, finite expiresAt, existing source bearer, exact operations, gatewayPublicKey and actorPublicKey. Insights additionally pins the source-issued UUID connectionId and connectionBindingDigest. Mail pins the source-issued hex64 connectionId, mailboxBinding and selectionRevision. These values come from reviewed source consent/configuration; clients cannot supply them as tool arguments. Ambiguous duplicate connections are denied. Configuration values and source bearers are never returned by tools/list.

Insights reads normalize the exact source schema and sign the version-1 context: fixed audience, approved opaque connection ID and binding digest, exact operation and normalized selection. A source-issued no-data preparation at the fixed operations path supplies a bounded operation ID; its exact context and finite expiry must match the stored approval. Execution uses only the fixed read-analytics/export-analytics paths. Read and export require separate Roles actions on analytics:permissioned. Native product/page filters and export approval remain source-owned.

Mail first prepares a source-issued challenge at the fixed `/api/integrations/mcp/operations` path. It returns no message data and must independently enforce current enrollment and native consent. Its version, expiry, descriptor, exact selection/content/version and source operation UUID are checked against the approved connection. Roles then authorizes mail:selected-read with separate metadata/plain actions. Only the fixed selected-message MCP tool is called; the source operation ID is conveyed in `x-bittrees-mcp-operation-id`. The challenge endpoint and production source provider are separate Mail work and remain unwired until reviewed.

RolesConsumer retains its existing effect(parameters, decisionEnvelope) interface and adds an optional third argument containing only the original public request, gateway signature, principal signature and verified decision envelope. It exposes no keys or signing functions. The full wrapper is sent in `x-bittrees-mcp-decision` as canonical base64url JSON, at most 12 KiB decoded/16 KiB encoded. The source independently verifies pinned keys, exact actor/connection/tuple/digest and all native authority. A header is a carrier, not authority.

The source reserves a signed request ID once durably, binding operation and parameters, and rechecks the original execute decision at dispatch and result release within the unchanged maximum five-second validity. The gateway also rechecks exact connection configuration, original signatures, parameters and decision before dispatch and before returning any data. The source must return exact Request-Id, Operation-Id and Decision-Digest receipt headers (digest of the canonical decision envelope); legacy bearer-only responses without these receipts are rejected. Expired or uncertain outcomes are held, with no automatic retry or TTL extension. Delayed queues need a separately reviewed fresh-proof protocol; this implementation does not invent one. Source dispatch/result reservation and final-delivery semantics are not implemented by the gateway.

Before activation, verify the actual enrolled actor, exact current Roles and source connection mappings, source consent and per-message or per-page permissions, current source implementations and durable replay fences, applicable TLD/Safe approvals, finite expiry, and ongoing cost coverage. The raging.eth label alone identifies no enrolled actor. Native lease/device pairing is not established by synthetic delegated-actor tests. A source-only exception or shared sign-in never substitutes for enrollment or current execution authority.
